# Product Specification

## 1. 產品定位與目標

KDE Window Size Screenshot 是 KDE Plasma 桌面上的指定尺寸視窗截圖工具。使用者先設定一組或多組截圖尺寸，再透過小型操作視窗或全域快捷鍵選取目標視窗。程式負責鎖定視窗、準備隔離的截圖顯示環境、完成精確尺寸截圖，並還原原本的視窗與桌面狀態。

主要使用情境：使用者設定 1280 × 800，將滑鼠移到目標視窗並按下 Shift + Print Screen，程式直接截取滑鼠所在視窗，不需要再點擊。

## 2. 產品原則

- 操作介面精簡，日常截圖不需要開啟大型設定頁。
- GUI 與快捷鍵使用同一個 Capture Controller 與 Capture Backend。
- 指定尺寸是最終 PNG 的實際像素尺寸，不是僅設定視窗外框尺寸。
- 預設包含視窗標題列與邊框。
- 不干擾主要螢幕、桌面排列或其他視窗。
- 不支援的視窗或不安全的顯示環境必須中止，不可默默降級。
- 截圖失敗時優先保護與恢復桌面，不以完成截圖為優先。
- 不保存截圖歷史；僅顯示最近一次截圖的結果資訊。

## 3. 小型快速操作視窗

### 3.1 啟動與尺寸

程式啟動時只顯示小型快速操作視窗。此視窗應緊湊、不佔據過多桌面空間，避免不必要的標題、說明、卡片與留白。

### 3.2 必要元素

- 應用程式標題與圖示。
- 右上角齒輪圖示：開啟獨立的大型 Settings 視窗。
- 關閉按鈕：結束程式。
- Profile 下拉選單，選項直接顯示「Profile 名稱 — 寬度 × 高度」。
- 明確的 Capture Window 按鈕。
- 預設快捷鍵提示：Shift + Print Screen。
- Last capture：顯示最近一次截圖的簡要結果，例如成功或尚無截圖。

### 3.3 明確禁止的多餘內容

- 不顯示 CAPTURE PROFILE 標籤。
- 不在 Profile 下拉選單下方重複顯示尺寸、Default badge 或 decorations 詳細資訊。
- 不顯示「Settings → Open full settings window」提示文字。
- 不顯示圖片預覽。
- 不保存或呈現多筆截圖歷史。

小型視窗上的齒輪只負責開啟完整 Settings。這與 Settings 的 Profiles 頁面不同：Profiles 頁面不得使用齒輪管理 Profile。

### 3.4 視窗按鈕行為

- Minimize：一般最小化至 KDE 工作列，不縮至系統匣。
- Close：直接結束程式。
- 最小化後可透過工作列或系統匣重新開啟。
- 系統匣左鍵：開啟小型 GUI。
- 系統匣右鍵：顯示系統匣功能選單。

## 4. 截圖操作流程

### 4.1 快捷鍵流程

預設快捷鍵為 Shift + Print Screen。

1. 使用者按下快捷鍵。
2. 程式在快捷鍵事件發生時取得滑鼠所在視窗的 Window ID。
3. 不要求使用者再次點擊視窗。
4. 使用目前預設 Profile。
5. 執行環境預檢與視窗狀態快照。
6. 在安全閘門允許的條件下執行截圖。
7. 還原視窗及桌面。
8. 顯示非干擾式 KDE 通知。
9. 不開啟 GUI 或圖片預覽。

若無法可靠取得滑鼠所在視窗、視窗 ID 無效或目標不支援，必須停止並通知原因。

### 4.2 GUI 按鈕流程

1. 使用者在小型視窗選擇 Profile。
2. 按下 Capture Window。
3. 小型 GUI 隱藏。
4. 進入視窗選取模式。
5. 滑鼠移入可選取視窗時顯示高亮邊框。
6. 使用者點擊目標視窗確認。
7. 鎖定目標視窗 ID。
8. 顯示獨立的小型進度視窗，呈現目前處理階段。
9. 執行截圖與復原。
10. 顯示 KDE 通知。
11. 重新顯示小型主畫面。

GUI 發起的截圖完成後必須返回小型主畫面；快捷鍵發起的截圖不應主動開啟 GUI。

### 4.3 取消

在視窗選取階段按下 Esc：

- 立即取消。
- 不調整目標視窗。
- 不改變螢幕或桌面配置。
- 清除選取提示。
- 恢復小型 GUI。

## 5. Capture Profiles

### 5.1 Profile 欄位

每個 Profile 至少包含：

- 名稱。
- 寬度（像素）。
- 高度（像素）。
- 是否為預設 Profile。

### 5.2 Profile 功能

支援新增、修改、刪除、重新命名、設定預設 Profile，以及選擇目前使用的 Profile。

### 5.3 小型視窗

Profile 下拉選單顯示名稱與解析度，例如：

- Default — 1280 × 800
- Full HD — 1920 × 1080
- HD — 1280 × 720

不在下拉選單下方重複顯示 Profile 詳細資訊。

### 5.4 Settings 的 Profiles 頁面

選擇 Profile 後，直接在同一個 Profiles 頁面編輯該 Profile 的名稱、寬度與高度。

頁面應提供：

- Profile 下拉選單。
- Profile name 欄位。
- Width 欄位。
- Height 欄位。
- Set as default 控制。
- New 操作。
- Delete 操作。

不提供 Manage Profiles 文字按鈕，不使用齒輪，不開啟獨立 Profile 管理 Dialog。

Profile 編輯屬於 Settings 的暫存變更。Apply 才正式保存；Cancel 放棄本次尚未套用的變更。切換 Profile 時不得意外遺失尚未套用的其他 Profile 編輯內容。

尺寸欄位必須驗證為正整數。名稱不得為空。實作可補充必要的輸入驗證，但不得改變上述操作方式。

## 6. Settings 視窗

完整設定使用獨立、較大的 Settings 視窗。

### 6.1 版面

左側垂直分類選單，右側顯示目前分類內容。

分類：

1. Profiles
2. Shortcut
3. Output
4. Application
5. System

### 6.2 套用機制

設定修改先暫存：

- Apply：驗證並保存所有待套用設定。
- Cancel：放棄所有尚未套用的修改。
- 設定保存於 KDE 使用者設定目錄。
- 程式重新啟動後自動載入已保存設定。

### 6.3 Shortcut

- 預設 Shift + Print Screen。
- 提供 Record Shortcut 操作。
- 使用者按下 Record Shortcut 後，再按想使用的組合鍵。
- 偵測與 KDE 或其他程式的快捷鍵衝突。
- 發現衝突時明確提示，讓使用者修改；不得未經同意覆寫其他程式的快捷鍵。

### 6.4 Output

- Copy screenshot to clipboard：獨立啟用。
- Save screenshot as PNG：獨立啟用。
- 兩者可分別設定，但至少須啟用一種。
- 預設輸出目錄為 ~/Pictures/Screenshots。
- 路徑文字欄位搭配 Browse 按鈕。
- Browse 使用 KDE 原生資料夾選擇器。
- 輸出目錄不存在時，需提供安全建立或錯誤提示。

### 6.5 Application

呈現應用程式操作行為與目前設定，例如最小化、關閉、系統匣行為及不提供自動啟動功能。此頁不應提供登入 KDE 自動啟動選項。

### 6.6 System

提供環境檢查、截圖引擎檢查、最近執行技術紀錄摘要及複製診斷報告功能。

## 7. 輸出規格

### 7.1 精確尺寸

指定尺寸代表最終 PNG 的實際像素寬高。標題列與邊框包含在該尺寸之內。

例如 Profile 設為 1280 × 800，最終 PNG 必須是 1280 × 800，而不是 1280 × 800 的內容區再額外加上標題列。

不得將錯誤尺寸的截圖事後縮放，並宣稱完成精確尺寸擷取。

### 7.2 檔名

建議格式：

WindowName_YYYYMMDD_HHMMSS.png

視窗名稱中的檔案系統不合法字元必須清理。若同名檔案已存在，自動附加流水號，絕不覆蓋既有圖片。

### 7.3 剪貼簿

若啟用 Copy to clipboard，截圖完成後將最終 PNG 影像複製到系統剪貼簿。剪貼簿內容應為影像資料，不應只複製檔案路徑。

### 7.4 最近一次結果

不保存截圖歷史。小型 GUI 只呈現最近一次結果的狀態或簡短資訊，不顯示圖片預覽。

## 8. 通知與進度

GUI 截圖時顯示獨立小型進度視窗，顯示處理階段；完成後回到小型主畫面。

快捷鍵截圖採非干擾式 KDE 通知，不開啟 GUI。

通知至少區分：

- 截圖成功且桌面已恢復。
- 截圖失敗但桌面已恢復。
- 桌面復原失敗，需要使用者處理。

只有確認桌面已恢復，才能顯示一般成功訊息。

## 9. 系統匣

右鍵選單包含：

- Capture
- Select Profile 子選單
- Open GUI
- Quit

左鍵開啟小型 GUI。系統匣 Capture 使用目前選定 Profile，並直接截取滑鼠所在視窗。

## 10. 平台與發行

第一版支援 Kubuntu 24.04、KDE Plasma、X11。

Wayland 第一版不支援。偵測到 Wayland 時顯示尚未支援的原因，並禁止執行截圖。

第一版採 AppImage 發行。Python、PySide6 與應用程式本身打包進 AppImage；X11/KDE 系統工具由主機提供，啟動時檢查必要依賴。

不提供程式內自動更新。使用者從 GitHub Releases 手動下載新版。

不提供登入 KDE 自動啟動功能。

## 11. 診斷與紀錄

保留最近五次執行的技術紀錄，不保存截圖內容。

診斷報告可包含工作階段類型、必要指令檢查、虛擬顯示能力檢查、截圖階段、復原結果與錯誤原因。

不得將截圖影像或剪貼簿內容寫入日誌。
